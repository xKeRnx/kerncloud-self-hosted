# Workspace suite — local release 0.21

## Available workflows

- **Team**: invite an existing or new customer by their account email; open the invitation after signing in. Owner, administrator, editor and viewer roles are enforced at the API. Owners retain account billing, connector-host and protected environment access. Editors can work on tasks and answer questions; they cannot approve external actions. Viewers can search/read results and mark their own notifications read. Invitations expire after seven days and are single-use. SMTP uses the existing admin mail configuration; the invitation link is also shown once to the inviter.
- **Work accounts**: the platform administrator configures separate OAuth clients under Work accounts → Admin. Register the exact callback URLs shown there with Google, Microsoft and GitHub. These clients are independent of social login. OAuth state is session/user/workspace-bound, expires after ten minutes and uses PKCE. Credentials and refresh tokens stay encrypted on the platform. Connections start with **no agent grants and no platform write permission**. Enable individual agents explicitly. Mail send, calendar create and GitHub publication require exact, revision-bound Decisions approval. Uncertain external writes are never automatically replayed. Disconnect locally, and revoke the provider grant there if complete provider-side revocation is desired. Google sensitive/restricted scopes and Microsoft tenant consent may require provider approval before public release.
- **Projects**: assign a development environment, HTTPS GitHub URL, new working branch and optional application port. `project_action` offers clone, status, test, diff and local commit. `environment_process` waits for longer commands. Public clone is anonymous; private Git clone currently needs customer-configured Git authentication in that environment. Platform OAuth tokens are never injected into Git command lines. `app_action/github_publish` creates an immutable commit, a **new** branch and a draft PR through GitHub REST, after explicit approval. The first publication input is deliberately bounded to 20 KB total text and 20 files; existing branches are never force-updated. For larger/binary changes, use the existing container Git setup. Running previews use the protected development gateway and code-server `/proxy/<port>/`; the application must already be listening on that port. Running preview access currently remains owner-only. Static deliverable previews are available to authorized team readers.
- **Project search**: PostgreSQL full-text search across uploaded text, current deliverables, conversations and project memory; bounded excerpts, line ranges, source IDs and SHA256. No embedding or model calls. Agent tools `search_project` and `read_project_source` avoid copying whole files. Search honors memory exclusions and tenant boundaries. Source text never grants tool permissions.
- **Briefings**: event notices for task completion/failure/questions and a daily consolidated overview. Configure timezone, hour, quiet hours, language and optional owner email. Daily emails are explicitly opt-in, use the existing encrypted outbox, and wait through quiet hours. In-app notices remain available immediately. Deduplication is workspace-wide; read status is per person. Briefings spend no model tokens. Existing cron/webhook automations remain separately budgeted. This release does not poll private inboxes in the background without a separately configured automation.
- **Office deliverables**: `create_office` creates editable DOCX paragraphs, XLSX sheets with literal typed cells, and PPTX text slides. Files appear in the existing result list, preview and ZIP download. The preview represents content, not Microsoft Office pagination. Generated ZIP/XML is checked before publication; no macros, external spreadsheet links or implicitly executable formulas are generated. Complex templates, charts, images and formula recalculation are not included in this first exporter.
- **Quality & cost**: explicitly start two metered AI tasks (website delivery and autonomous repair) with an active selected model. The total token/credit cap is split into fixed per-case caps; each case uses the existing atomic reservations, retry limits and worker fencing. Concurrent maintenance calls cannot create duplicate runs. Success requires deliverables, known usage and independent fixed browser assertions. Agent self-reporting does not count. Cancel stops active case runs. No test is started by merely opening the page; inactive models are preserved.
- **Environment budgets**: optional idle stop and explicit agent auto-wake on the same allowed host. Running/queued/uncertain work prevents idle stop. Gateway use and tools refresh activity. Wake rechecks the task lease, agent grant, plan, host and runtime allowance. Stopped containers retain files and slots. New customer images `kerncloud-browser:0.5` and `kerncloud-development:0.5` monitor project storage, guard direct writes and kill monitored commands above the configured project budget. This is a controller safeguard, **not a filesystem hard quota**. Checkpoints, package caches and image layers need separate operator disk planning. Existing containers require a planned image recreation before their controller gains storage guarding; the update never resets customer files automatically.

## Verification and deployment

Use a dedicated `_test` PostgreSQL database. `COMPETITIVE_FOCUS=1 npm run test:integration` exercises the new suite. Full release checks: typecheck, unit tests, full integration suite and Next.js build. Protocol fixtures are isolated tests and do not prove real Google/Microsoft/GitHub consent or real model quality. No real provider account or model has been enabled by installing this release.

Before public release, verify real provider app consent, callback origins, SMTP, tenant invitation abuse limits, retention/export/deletion, operational monitoring, backups/restores and the existing `OPERATIONS.md`. Provider terms, legal compliance and production readiness require separate review. Local installation preserves the database, volumes, original sources and rollback images.
