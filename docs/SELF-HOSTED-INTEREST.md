# Self-hosted demand pilot and navigation (0.26)

The bilingual landing-page section #self-hosted collects non-binding interest, not orders. Email and explicit opt-in are required; company, team size, deployment requirements and use case are optional. No price, release date, offline support or product availability is promised. No messages are queued or sent. Addresses remain unverified and the admin dashboard labels them accordingly; do not interpret entries as verified customers or automatically add them to newsletters.

The opt-in text is versioned self-hosted-interest-v1. Records expire after 180 days and are excluded from admin views/exports after expiry; hourly housekeeping physically removes expired records when the scheduler is running. Duplicate submissions do not overwrite an active record or extend retention. A fresh opt-in may replace an expired record. An email withdrawal request can be handled by the operator using the documented imprint contact and the admin deletion action. The public form itself needs no account. There is no double-opt-in mechanism yet; validate email ownership and review consent before any later outreach campaign.

Platform administrators can search, filter, change status, add internal notes, permanently remove individual entries and export up to 5,000 filtered entries. Updates require the current revision; stale writes are rejected. CSV fields are escaped and formula-prefixed inputs neutralised. Exports contain personal data; the operator must protect them and include them in deletion workflows. Audit rows contain entry IDs, not contact details. Account data exports include matching waitlist details; account deletion also removes those entries. Backups follow the operator's existing retention and restoration procedure.

The form has a honeypot, input limits, per-email throttling and a global 200 requests/15-minute intake cap shared through PostgreSQL. No raw client IP or browser fingerprint is stored for this feature. These are basic pilot abuse limits, not email verification or comprehensive bot detection. Public responses do not disclose whether an address is already listed. Reverse-proxy flood protection and correct operator/privacy information still need verification before public rollout.

The sidebar now focuses on Overview, Projects and Decisions. Team & tools and Manage workspace are collapsible; the selected section opens when navigating directly to a child route. Billing and platform administration remain directly accessible. Workspace switching uses the existing picker. Project navigation holds tasks, team chat, files, memory, search, timeline, routines and environments, with the selected project shown above them. Existing direct URLs and server permissions are preserved. This is navigation grouping, not a change to project access rights.

Tests use only a dedicated _test database, with no real model calls, purchases or outbound emails.
